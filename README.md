# Attendance Nowcast: a data assimilation learning series

Estimate a theme park's **final daily attendance** and revise that estimate every
hour as cumulative gate counts arrive, using a Kalman filter written by hand in
NumPy. The pre-open daily forecast is the prior; each hour's gate count tightens it.

This is a learning project: every notebook explains the concept in plain English
before any code, and the filter math lives in small, commented functions.

## ⚠️ Simulated data disclosure

**All attendance, gate-count and weather data in this repository is SIMULATED.**
It describes a fictional park in **Tampa, Florida** (`park_id = SIM_TAMPA_FL`),
generated by `src/nowcast/simulate.py`, with Florida seasons, a Tampa-like climate
with wet-season afternoon thunderstorms, US + Florida holidays, random early/late
crowds and day-to-day noise. The park is placed in Florida so the feature families
of the [Attendance-Projections](https://github.com/lmansf/Attendance-Projections)
model (weather, holidays, calendar) carry over.

Why simulated: the original Kaggle source (`ayushtankha/hackathon`) has daily
attendance but no hourly gate entries, and it wasn't reachable from the build
environment. Every table row carries `source = 'simulation'`, and every chart title
says SIMULATED.

## Data layer: built for production data

The notebooks read from a SQL database through SQLAlchemy:

* **Default:** a local SQLite file, `data/nowcast.db`, created and filled with
  simulated data automatically on first run. No setup needed.
* **Production:** point `NOWCAST_DB_URL` at your database, e.g.
  `postgresql+psycopg://user:pass@host/db` (install that database's driver too),
  and create the tables from [`src/nowcast/schema.sql`](src/nowcast/schema.sql).

Every table has a **`source`** column (`'simulation'` or `'production'`) that is part
of the primary key, so both kinds of rows can live side by side. Loaders require
`source` explicitly, and reloading simulated data never touches production rows.

| Table | One row per | Key columns |
| --- | --- | --- |
| `parks` | park | open/close hour, timezone |
| `daily_attendance` | park-day | `attendance` (final total) |
| `hourly_entries` | park-day-hour | `cumulative_entries` at the end of clock hour `hour` |
| `daily_weather` | park-day | temperature, humidity, precipitation |
| `simulation_log` | simulated park-day | hidden truth (planned demand, crowd pace, storm hour), simulation only |

To switch a notebook to real data: load your rows with `source = 'production'`,
then set `SOURCE = "production"` at the top of the notebook. `f_t`, `R_t` and the
tuning knobs are all re-estimated from whichever source you choose.

## How to run

```bash
pip install -r requirements.txt   # also installs src/nowcast in editable mode
python -m pytest                  # unit + end-to-end tests
jupyter lab notebooks/            # run any notebook top to bottom
```

Python 3.11+. The filter math is pure NumPy: no filter libraries and no AI/LLM APIs
anywhere. SQLAlchemy is used only for portable database access, and `holidays` for
the US/Florida calendar.

## Layout

```
src/nowcast/
  kalman.py     predict(), update(), run_filter(): the 1D filter
  arrivals.py   arrival curve f_t + SIMULATED intraday arrivals
  simulate.py   SIMULATED Tampa, FL park (daily, hourly, weather)
  db.py         SQL access; every loader filters on `source`
  schema.sql    portable table definitions
  forecast.py   same-weekday baseline forecast (the prior)
  noise.py      empirical R_t estimation (constant / absolute / relative)
  runner.py     run the nowcast over one day or many
  scoring.py    MAE and ±2σ coverage by hour
  daytype.py    peak (weekend/holiday) vs regular days
  style.py      shared plot colours
notebooks/      the learning series
tests/          pytest suite
```
